## Contrato aditivo y compatibilidad

Misma ruta:

`GET /api/v1/stores/{storeId}/areas/{areaId}/equipment/{equipmentId}/alerts`

- Nuevos parámetros opcionales `from`, `to`: ambos valores presentes o ninguno. ISO con segundos, Z o ±HH:mm explícito, hasta seis decimales; UTC. Inicio incluido/fin excluido, `from < to`, máximo técnico 31 días (convención existente de historial, no retención de negocio). + debe enviarse %2B.
- Base temporal **CreatedAtUtc**: creación/detección en servidor almacenada en la alerta, distinta de CapturedAtUtc y de AcknowledgedAtUtc. No se recalcula fecha o estado. Ambos valores ausentes conservan el listado anterior; MVC normaliza strings vacíos a ausentes, por lo que ambos vacíos equivalen a no filtrar. Un límite único o valor inválido → 400.
- Conserva `status=OPEN|ACKNOWLEDGED`, `severity=CRITICAL|NON_CRITICAL`, page=1/pageSize=20, tamaño 1–100 y offset Int32. Composición de todos los filtros antes de paginar.
- Conserva CreatedAtUtc descendente e Id ascendente, DTO AlertResource y página items/page/pageSize/hasMore. Sin coincidencias → 200 vacío, hasMore=false.
- Misma identidad humana IAM y titularidad/ascendencia Store→Area→Equipment. Ajeno/inexistente/padres cruzados → 404 genérico. Anónimo/solo Edge → 401. No roles nuevos, bypass Admin, propietario aportado por cliente o autoridad de ingesta para leer historia.

Ejemplo sanitizado:

```http
GET /api/v1/stores/{storeId}/areas/{areaId}/equipment/{equipmentId}/alerts?from=2026-01-01T00:00:00-05:00&to=2026-01-01T02:00:00-05:00&status=OPEN&severity=CRITICAL&page=1&pageSize=20
```

El intervalo representa 05:00Z ≤ CreatedAtUtc < 07:00Z. El DTO sigue mostrando captura, creación, severidad original/presentación y auditoría de ACK. ACK no es resolución. Sin modificación de ingesta, umbrales, detecciones, equipos, firmware o frontend. Retirada no añade restricciones de consulta nuevas; el caso aislado conserva acceso con dispositivo retirado. No se reejecutó todo el recorrido histórico de retirada.

Offset sigue sin snapshot entre solicitudes: nuevas alertas o cambios de estado pueden desplazar páginas. Id único desempata fechas, no congela el conjunto. No se promete consistencia de exportación o comportamiento offline. La UI y consumidores reales no se modifican ni se acreditan.

## Implementación y fuentes técnicas

Controller añade los dos parámetros; servicio verifica acceso antes de parsear y conserva validadores previos. Repositorio aplica los predicados de CreatedAtUtc a IQueryable, luego orden/Skip/Take y finalmente ToListAsync. No carga todos los registros ni filtra páginas en memoria. Se revisó y reutilizó (EquipmentId,CreatedAtUtc); no DDL ni modificación de modelo EF.

El parser previo de MeasurementHistoryQuery se extrae literalmente a Shared/Application/Time/ExplicitUtcInterval: mismas formas ISO, UTC, precisión y límite de 31 días, sin duplicación entre módulos. La validación/página del historial de mediciones queda igual. Las cuatro pruebas previas de ese historial siguen pasando.

Stack identificado en csproj: ASP.NET Core/net9.0, EF Core 9.0.5, Npgsql EF 9.0.4. Fuentes oficiales verificadas antes de implementar:

- [ASP.NET Core 9 model binding](https://learn.microsoft.com/en-us/aspnet/core/mvc/models/model-binding?view=aspnetcore-9.0): parámetros de query y valores opcionales. Se usa la versión del proyecto sin cambiar runtime.
- [EF Core pagination](https://learn.microsoft.com/en-us/ef/core/querying/pagination): Skip/Take y orden único; documenta desplazamientos concurrentes de offset.
- [Npgsql datetime](https://www.npgsql.org/doc/types/datetime.html): timestamptz usa UTC y precisión microsegundo; los límites se convierten a UTC sin redondeo.

No se incorporan recomendaciones de infraestructura o paquetes de esas páginas. Todo se comprueba contra las versiones existentes y ejecución local.
