## Contrato aditivo

`GET /api/v1/stores/{storeId}/areas/{areaId}/equipment/{equipmentId}/measurements`

| Parámetro | Regla |
|---|---|
| from, to | Requeridos. ISO fecha/hora con segundos y Z o ±HH:mm explícito; 0–6 decimales. Sin cultura/zona local implícitas. |
| Intervalo | UTC, CapturedAtUtc ≥ from y < to; from < to, máximo 31 días. No filtra por recepción. |
| page | Default 1, positivo; offset debe caber en Int32. |
| pageSize | Default 20; entre 1 y 100. |

El máximo de 31 días es un límite técnico documentado de este endpoint, no una regla de retención de negocio. Se pueden recorrer ventanas consecutivas. Se rechazan fracciones de más de seis dígitos para no truncar límites sobre la precisión microsegundo de PostgreSQL. No hay fecha implícita ni redondeo. Un `+` en query debe enviarse `%2B`.

200: `{items,page,pageSize,hasMore}`; sin total global. Equipo autorizado sin vínculo/muestras → página vacía, no alta ni fallback demo. 401 anónimo/solo clave Edge, 404 genérico para ajeno/inexistente/ascendencia incompatible, 400 para parámetros inválidos (ValidationProblemDetails automático o message controlado, como el controller existente). IDs de jerarquía conservan su validación actual.

Cada item tiene únicamente campos almacenados:

| Campo | Significado |
|---|---|
| readingId | Identidad persistida dentro del vínculo del equipo |
| capturedAtUtc / receivedAtUtc | Captura y recepción separadas, normalizadas/leídas como UTC |
| timestampBasis | EXPLICIT_OFFSET o EDGE_UTC_ASSUMED almacenado, sin inventar zona histórica |
| voltage / current | Voltios V / amperios A |
| powerFactor / frequency | Adimensional / Hz |
| source | Origen almacenado, incluido replay |
| detectedAnomalyType / detectedSeverity | Detección asociada almacenada, nullable |

No incluye claves, hashes, perfiles, ActivePowerKw derivado, kWh, costos, promedios ni sumas. Detección nula no significa NORMAL: puede no haberse evaluado una captura atrasada. Estos campos no son estado actual, ACK ni resolución. Una alerta ACK del fixture conserva la detección High en el historial; la respuesta no incorpora su estado.

Orden: CapturedAtUtc ascendente y ReadingId ascendente con collation C de PostgreSQL. BindingId/ReadingId es PK y el vínculo por equipo es único e inmutable en el corte vigente. Offset/página conserva la convención local. No hay snapshot entre peticiones: las llegadas tardías pueden desplazar offsets y causar repeticiones/omisiones. Volver a consultar el intervalo desde la primera página y deduplicar por ReadingId del equipo permite reconciliar datos ya recibidos; no garantiza cierre frente a llegadas futuras. Un to fijo no congela recepciones tardías.

Ejemplo exclusivamente sintético (sustituir IDs de ruta por los emitidos por altas):

```http
GET /api/v1/stores/{storeId}/areas/{areaId}/equipment/{equipmentId}/measurements?from=2026-01-01T00:00:00-05:00&to=2026-01-01T02:00:00-05:00&page=2&pageSize=2
Authorization: Bearer <JWT-del-titular>
```

```json
{"items":[{"readingId":"tie-z","capturedAtUtc":"2026-01-01T06:00:00Z","receivedAtUtc":"2026-01-02T08:00:00Z","timestampBasis":"EXPLICIT_OFFSET","voltage":220,"current":2,"powerFactor":0.9,"frequency":60,"source":"EdgeBufferReplay","detectedAnomalyType":null,"detectedSeverity":null}],"page":2,"pageSize":2,"hasMore":false}
```
