## Contrato, seguridad y compatibilidad

Nueva ruta aditiva: `GET /api/v1/stores/{storeId}/alerts`.

| Parámetro | Regla |
|---|---|
| equipmentId | Opcional; si se envía, debe identificar un equipo del local autorizado a través de su área. Vacío, blanco, mal formado, ajeno, de otro local incluso del mismo titular o inexistente: 404 genérico. No se descarta silenciosamente. |
| from/to | Ambos valores o ninguno. Parser ExplicitUtcInterval sin cambios: ISO con segundos, Z o ±HH:mm explícito, hasta 6 decimales; normalización UTC, [from,to), inicio menor que fin, máximo técnico 31 días. + como %2B. |
| status | OPEN o ACKNOWLEDGED; opcional, conserva M3.11. |
| severity | CRITICAL o NON_CRITICAL; opcional, conserva M3.11. |
| page/pageSize | 1/20 por defecto, tamaño 1–100, página positiva y offset Int32. |

CreatedAtUtc sigue siendo fecha de creación de la alerta, no captura ni ACK. Sin fechas permite todo el periodo paginado; MVC normaliza strings vacíos, ambos vacíos equivalen a ausencia como M3.11. Un límite único/fechas inválidas y filtros/paginación inválidos → 400. ApiController puede rechazar conversiones inválidas de enteros antes del servicio; no se uniforman errores ajenos a este corte.

Identidad humana IAM tomada de Items["User"] del servidor. Titularidad del local antes de validar filtros en el servicio; con equipo, comprobación de equipo→área→local. Ajeno/inexistente → 404 `{"message":"Resource not found."}`. Un ID de local mal formado conserva el 400 de jerarquía. Anónimo/solo clave Edge → 401. Ni rol Admin ni clave Edge conceden bypass. No se exige autoridad de ingesta, AllowedDeviceIds o perfil activo para leer historia del local.

Respuesta existente `HierarchyPage<AlertResource>`: {items,page,pageSize,hasMore}. AlertResource ya tiene equipmentId: se conservan exactamente sus 12 campos; ningún DTO nuevo ni campos personales/credenciales adicionales. Sin resultados → 200 items=[], hasMore=false. Orden CreatedAtUtc DESC/Id ASC global entre equipos. No se cambia la ruta previa de equipo, detalle o ACK; con equipmentId la nueva consulta da la misma página que el historial del equipo.

Ejemplo sintético (sustituir IDs válidos):

```http
GET /api/v1/stores/{storeId}/alerts?from=2026-01-01T00:00:00-05:00&to=2026-01-01T02:00:00-05:00&status=OPEN&severity=CRITICAL&pageSize=20
GET /api/v1/stores/{storeId}/alerts?equipmentId={equipmentId}
```
