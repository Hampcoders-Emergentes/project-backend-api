## Auxiliar y formato

Ubicación: `tools/DeviceIdReconciliation/`. Su [manual operativo](../tools/DeviceIdReconciliation/README.md) define schemaVersion 1, inventario Assets, observaciones de tres fuentes y mappings adicionales explícitos con evidenceRef. Rechaza propiedades desconocidas/JSON duplicadas, campos necesarios ausentes y fuentes no admitidas. Lee un único archivo local de hasta 16 MiB; no carga configuración de la API o variables de credenciales, no abre URLs ni conexiones.

Informe: IDs exactos, matchedAssets, observations/mappings y evidencia aportada, incidencias, presencia de comandos en el corte y clasificación Supported/Unmatched/Ambiguous/DemoReview/Review. Siempre `grantsAccess: false`; no genera AllowedDeviceIds ni archivo de configuración. Incluye snapshotId, environment declarado e inputSha256 de los bytes de entrada. El informe es determinista y no verifica por sí mismo la autenticidad de una referencia de evidencia.

No se deduplican filas de forma silenciosa, no se normalizan IDs y no se resuelven colisiones eligiendo el primero. La serie solo se relaciona con su ID mediante la fila explícita de inventario. Los mappings requieren evidencia y destino existente; no sustituyen los valores observados por valores inventados. La falta de comandos es un indicador del corte, **no motivo suficiente para invalidar un dispositivo legítimo**.

Los casos Supported todavía requieren revisión de legitimidad, contrato de ID, alcance, vigencia y decisión humana. Una serie puede corresponder a un inventario y aun así no ser una cadena válida para el DeviceId de history. No se transforma automáticamente para cumplir ese contrato.
